# Facts Interview

Факт-фаза идёт **после** концепт-фазы. Цель — собрать данные для PRD.
Они сохраняются в `tech.md` папки фичи (шаблон и правила — `SKILL.md`, шаг 4).

**Правила:**
- Макс 3 раунда (раунд рисков опционален и не считается)
- Не более 3–4 вопросов за раз
- Пропускай очевидное (что уже выяснилось на концепт-фазе)
- Пробелы не тянут интервью: продуктовые → раздел «Что осталось обсудить»
  в notes, технические → раздел «Открытые тех-вопросы» в tech.md

---

## Раунд 1: Контекст и материалы

Цель — конкретика по пользователям и материалам.

- Какая роль / тип юзера — точно? (внутренняя команда / клиент / админ /
  внешний пользователь без аккаунта)
- Что сейчас происходит без этой фичи? (текущий workaround или его отсутствие)
- Есть ли дедлайн или внешний триггер (метрика, жалоба, требование бизнеса)?
- Есть ли Figma / тикет / обсуждение / референс — ссылки?

---

## Раунд 2: Скоуп

- Что явно НЕ входит в эту итерацию? (чтобы не переделывать потом)
- Must-have vs nice-to-have среди FR?
- Рассматривали альтернативы? Почему выбрали этот подход?

---

## Раунд 3: Заданные технические ограничения (если нужны)

Пропусти, если пользователь не задавал технических ограничений. Технические
разделы tech.md тогда получают `нет данных — вариант обсудит create-prd`.

- Есть ли обязательная платформа, язык, сервис или ограничение среды?
- Есть ли существующий интерфейс или формат данных, который нужно сохранить?
- Есть ли известные зависимости или запреты на внешние сервисы?

Не проси пользователя выбирать библиотеку, структуру файлов, таблицы или
эндпоинты, если эти решения можно принять в `create-prd` по проекту.

---

## Раунд 4 (опциональный): Риски

Пропусти для простых фич. Включай если фича сложная или пользователь сам
упоминает риски.

- Какие риски: производительность / безопасность / UX?
- Есть ли части, которые ты пока не знаешь как реализовать?
- Что может пойти не так на релизе?

---

## Когда хватит

Хватит когда:
- Понятен пользователь, скоуп (что в / вне), хотя бы 2–3 FR
- Если на discovery всплыло тех-решение или альтернатива — оно понято и
  записано (куда — см. таблицу ниже)
- Пробелы зафиксированы: продуктовые — в notes «Что осталось обсудить»,
  неизвестные технические ограничения — в tech.md «Открытые тех-вопросы»;
  обычные инженерные решения оставлены для `create-prd`

**Не нужно знать всё.** Лучше зафиксировать пробелы, чем тянуть интервью
10 раундов. Это касается ТОЛЬКО фактов — концепт должен быть полным
(см. `concept-probing.md`).

---

## Куда записываются факты

Notes — документ **shared understanding**, не PRD-черновик. Поэтому
тех-детали и операционные факты в notes **не идут** — они записываются в
`tech.md`, откуда их берёт `/create-prd`. Каждый факт записывается
в одно место; если он уже есть в notes, в tech.md ставится ссылка
`см. notes, «<раздел>»`.

**В notes попадает только то, что меняет ПОНИМАНИЕ фичи.** Всё остальное —
в tech.md:

| Факт | Куда |
|------|------|
| Кто пользователь, в каком контексте | notes — «Для кого и какой опыт» |
| Существующий workaround / legacy | tech.md — «Контекст»; если legacy уже упомянут в notes «Что это» — ссылка на него |
| Дедлайн / триггер бизнеса | tech.md — «Контекст» |
| Figma / тикет / обсуждение | tech.md — «Контекст» |
| Что входит в итерацию и что явно вне | tech.md — «Скоуп» |
| FR с приоритетом must-have / nice-to-have | tech.md — «Функциональные требования» |
| Альтернативные ПОДХОДЫ к фиче (жанр, бизнес-модель), изменившие концепт | notes — «Ключевые повороты в discovery» |
| Альтернативы тех-решений и причины отказа | tech.md — «Альтернативы тех-решений» |
| Заданные пользователем стек, компоненты и маршруты | tech.md — «Стек и компоненты» |
| Уже заданные эндпоинты | tech.md — «API» |
| Уже заданная схема БД | tech.md — «БД» |
| Фоновые задачи, очереди, кэш, внешние интеграции | tech.md — «Фон, очереди, кэш, интеграции» |
| Уже существующие или заданные пользователем модули и файлы | tech.md — «Затрагиваемые модули и файлы» |
| Зависимости от сервисов / фич / команд | tech.md — «Зависимости» |
| Риски | tech.md — «Риски», списком, без матрицы R1–R5 |
| Открытые продуктовые вопросы | notes — «Что осталось обсудить», свободным списком |
| Открытые тех-вопросы (нет VPS, нет App Password, не выбран DNS) | tech.md — «Открытые тех-вопросы» |

Ничего из факт-фазы не остаётся только в истории разговора: `/create-prd`
может запускаться в новой сессии и читает только notes, tech.md и
репозиторий. Не записал факт — его не будет в PRD.
