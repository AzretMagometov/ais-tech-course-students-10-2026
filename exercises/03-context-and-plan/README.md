# Практика второй лекции: контекст, память, план и состояние

Четыре коротких блока повторяют действия со слайдов 8, 14, 20 и 23.
Выполняйте их по порядку в своей копии курса. Все пути ниже указаны от корня этой копии.

Понадобится агент с чтением и записью файлов. Обязательные шаги не требуют Git, Beads, GitHub CLI или дополнительных библиотек.
Команды Claude Code вводите в диалоге агента, а не в PowerShell.
[Памятка](../../materials/lecture-02/cheatsheet.md) различает управление в терминале и Desktop.

## Подготовка

Получите актуальные материалы. Если у вас ZIP, распакуйте новую копию в отдельную папку, сохранив прежние результаты.
Если используете Git, сначала выполните `git status --short --branch` в корне курса.
При чистом рабочем дереве выполните `git pull --ff-only`. При ошибке обновления сохраните сообщение и не сбрасывайте свои изменения.

Откройте корень курса в Claude Desktop → Code как локальную папку либо запустите `claude` из этой папки.
Проверьте, что агент видит `materials/lecture-02/lecture.md` и этот файл упражнения.
Выберите ручное подтверждение правок. Рабочие результаты будут в `exercises/03-context-and-plan/work/`; папка исключена из Git.

Если `work/` уже существует, сохраните её содержимое в отдельной папке перед новой попыткой.
Не просите агента молча перезаписывать прежние результаты.

## 1. Контекст

### Начали сессию: что уже загружено

В новой сессии вызовите `/context`.
Посмотрите, какие части занимают окно до первого чтения файла.
Ожидается, что место уже занято служебными инструкциями и правилами; точные числа зависят от среды.

### Нужный файл известен

Отправьте:

```text
@materials/lecture-02/lecture.md Чем очистка истории отличается от сжатия?
Ответь в трёх пунктах по разделу 1. Файлы не меняй.
```

Проверьте ссылку или действие чтения файла в ленте. Сверьте ответ с разделом 1.
Повторите `/context` и сравните состав контекста. Не ожидайте заранее заданного числа токенов.

### Побочный вопрос

```text
/btw Какой файл мы только что прочитали?
```

Ответ должен опираться на уже известный путь. Этот вопрос не требует нового поиска.
В Desktop можно открыть побочный чат: `Ctrl+;` на Windows или `Cmd+;` на macOS.

### Нужно остановить действие

Попросите агента найти в учебных Markdown-файлах упоминания слова «контекст», не меняя файлы.
Во время поиска нажмите `Esc`. Если поиск успел завершиться, остановка не была проверена: так и отметьте.
Проверьте, что выполненные до остановки действия остались в ленте.

Дополнительно в терминале очистите поле ввода и нажмите `Esc Esc`.
Выберите сообщение перед поиском и возврат только разговора. Проверьте полученную историю.
В этой попытке файловых правок нет, поэтому она не проверяет восстановление файлов.

### Сжать или начать заново

В терминале отправьте:

```text
/compact сохрани путь прочитанного файла и различие между очисткой и сжатием
```

В Desktop используйте `/compact`, если он доступен. В короткой сессии клиент может сообщить, что сжимать пока нечего.
Это допустимый результат. Если сжатие выполнено, проверьте сохранённые сведения и `/context`.

Для завершения блока в терминале дайте сессии имя через `/rename контекст-лекция-02`, затем выполните `/clear`.
Через `/resume` найдите прежний разговор. В Desktop используйте список сессий и кнопку новой сессии.
Проверьте различие: новая сессия без прежней истории, прежняя доступна отдельно.

## 2. Память

### Где находятся инструкции

В терминале выполните `/memory` и посмотрите доступные файлы инструкций и памяти.
Если в Desktop команды нет, откройте `CLAUDE.md` и `AGENTS.md` из корня курса вручную.
Проверьте, что `CLAUDE.md` подключает общие правила, а не содержит отдельную копию.

На Windows откройте в Проводнике `%USERPROFILE%\.claude`.
На macOS: Finder → `Cmd+Shift+G` → `~/.claude`; на Linux откройте эту папку в файловом менеджере.
Посмотрите структуру каталогов, не публикуя личные заметки или настройки.
Каталога автоматической памяти может ещё не быть, если агент не создавал записи.

### Сохранить заметное личное правило

```text
Прочитай CLAUDE.local.md в корне курса, если он существует.
Добавь правило: «Отвечай не длиннее пяти строк, если я не прошу подробно».
Не перезаписывай другие правила. Проверь исключение этого файла в .gitignore.
Не меняй общие инструкции. Сообщи путь и точный добавленный текст.
```

Подтвердите правку и откройте файл. Исключение `CLAUDE.local.md` уже включено в комплект.
При наличии Git проверьте в терминале: `git check-ignore CLAUDE.local.md`.
Также выполните `git ls-files -- CLAUDE.local.md`: вывод должен быть пустым.
Если файл уже отслеживается, не публикуйте его; разберите ситуацию отдельно. `.gitignore` не удаляет файлы из истории.

Откройте новую сессию в корне курса и спросите:

```text
Что такое контекст? Ответь кратко.
```

Проверьте длину ответа и загрузку `CLAUDE.local.md` через `/memory`, если команда доступна.
Если правило не применилось, проверьте выбранную папку, новую сессию и конфликтующие инструкции.
Не считайте одно совпадение стиля доказательством загрузки файла.

### Проверить происхождение сведений

```text
Какие правила этой учебной папки ты используешь?
Для каждого назови файл. Не перечисляй личные сведения из других проектов.
```

Откройте один названный файл и найдите соответствующую запись.
Если агент не может подтвердить источник, считайте утверждение непроверенным.

### Записать решение

```text
Создай exercises/03-context-and-plan/work/decisions.md, если его ещё нет.
Добавь решение с сегодняшней датой: результаты практики храним в work/ этого упражнения.
Причина: исходные материалы курса остаются пригодны для следующей попытки.
Отклонено: правки корневого README, поскольку это общее оглавление.
Не меняй другие файлы. Если запись уже есть, не дублируй её.
```

Откройте результат. В записи должны различаться выбранное действие, причина и отклонённый вариант.

## 3. Задачи и план

### Подготовить и поправить план

Включите Plan: переключатель под полем ввода в Desktop или `/plan` в терминале.
Отправьте:

```text
Подготовь план создания exercises/03-context-and-plan/work/summary.md.
Источник: materials/lecture-02/lecture.md.
Нужны разделы «Контекст», «Память», «Задачи и план», «Состояние».
В каждом: одна ситуация, действие и способ проверить результат.
Добавь относительную ссылку из summary.md на исходный текст лекции.
Рабочие файлы пока не меняй. Изменения разрешены только внутри work/ этого упражнения.
После одобрения первым шагом сохрани согласованный план в work/plan.md этого упражнения.
В плане нужны критерии готовности, шаги, открытые вопросы и состояние.
Для проверки продолжения раздели выполнение: сначала только раздел «Контекст», затем остановка.
```

Прочитайте предложенный план. Проверьте, что указаны четыре темы, ссылка, границы правок и остановка после первого раздела.
Внесите уточнение:

```text
Добавь критерий: все четыре раздела нужно сверить с источником.
В состоянии плана записывай фактические проверки и следующий шаг.
```

Если режима планирования нет, отправьте тот же запрос с ограничением на изменения и проверьте действия агента.

### Начать выполнение и остановиться на границе шага

Одобрите план с ручным подтверждением правок:

```text
Сохрани согласованный план в exercises/03-context-and-plan/work/plan.md.
Создай в summary.md только раздел «Контекст», проверь его и обнови состояние плана.
После этого остановись. Остальные три раздела пока не пиши.
```

Проверьте два файла. В памятке должен быть один тематический раздел, в плане — незавершённые шаги и следующий шаг.
Решение из практики 2 должно сохраниться. В терминале `Ctrl+T` позволяет посмотреть список шагов, если агент его создал.
Список шагов интерфейса не заменяет сохранённый файл плана.

### Восстановить работу

Начните новую сессию в корне курса. Не возвращайтесь в прежнюю через `/resume`: здесь проверяем восстановление по файлам.

```text
Прочитай exercises/03-context-and-plan/work/plan.md и фактический summary.md рядом с ним.
Сверь сделанное с планом. Что осталось и какой следующий шаг? Пока ничего не меняй.
```

Проверьте, что агент назвал готовый раздел «Контекст» и три оставшиеся темы.
Если он объявил всю задачу готовой, укажите расхождение и попросите перечитать файлы.

Затем поручите:

```text
Продолжи по сохранённому плану. Допиши оставшиеся разделы, проверь критерии и обнови состояние.
Изменяй только exercises/03-context-and-plan/work/.
```

Откройте результат и план. Проверьте один раздел самостоятельно.

### Трекер как следующий уровень

Посмотрите примеры Beads и GitHub Issues на слайде 18.
Если в вашей рабочей задаче уже есть трекер, найдите текущую карточку и её критерии готовности.
В учебном репозитории не создавайте публичные задачи и не инициализируйте Beads ради упражнения.

## 4. Состояние

Начните новую сессию в корне курса и отправьте:

```text
Проверь exercises/03-context-and-plan/work/ по критериям из plan.md.
Для каждого критерия покажи результат и основание: файл, фрагмент или команду с выводом.
Проверь четыре темы, ситуацию/действие/проверку в каждой и относительную ссылку на источник.
Если у копии есть Git, покажи ветку и изменения. Учти, что work/ исключена из Git.
Если Git нет, сообщи об этом и проверяй файлы напрямую.
Не выдумывай сборку и тесты: для этой Markdown-памятки нужны проверки содержания и ссылки.
Рабочие файлы не меняй. Назови невыполненное и непроверенное.
```

Проверьте один вывод самостоятельно: откройте `summary.md`, найдите четыре раздела и перейдите по ссылке.
Попросите показать, как проверено содержание одного раздела по исходному тексту.
Если найдена ошибка, сначала исправьте её отдельным поручением, затем повторите соответствующую проверку.

Для просмотра фоновой работы в терминале вызовите `/tasks`, в Desktop откройте меню ⋮ → Background tasks.
Пустой список относится к доступной клиенту фоновой работе, а не ко всем процессам компьютера.

## Завершение

В `work/` остаются `decisions.md`, `plan.md` и `summary.md`.
Отметьте для себя: что удалось восстановить, какая проверка подтвердила результат, где потребовалась помощь.
Незавершённый шаг или недоступная команда — допустимый результат попытки, если причина записана.

Результаты можно оставить локально. Не публикуйте их в общем репозитории.
Если правило пяти строк больше не нужно, удалите только добавленную строку из `CLAUDE.local.md`, сохранив остальные записи.
Общие файлы курса возвращать через `git restore` не требуется: упражнение не предполагает их изменения.
