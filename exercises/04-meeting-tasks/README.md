# Из транскрипта встречи в список задач

Вы соберёте инструмент, который выделяет поручения из разговора и записывает их в CSV. Проходите шаги по одному. После каждого запроса дождитесь результата и выполните проверку сами. Если проверка расходится с описанием, отправьте агенту команду, фактический вывод и ожидаемый результат. Продолжайте после повторной проверки.

## Подготовьте рабочую папку

1. Откройте терминал в корне скачанного репозитория, рядом с папками `materials` и `exercises`. На Windows используйте PowerShell.
2. Выполните `claude --version` и `uv --version`. Обе команды должны вывести версию. Если команда отсутствует, установите [Claude Code](https://code.claude.com/docs/en/setup) или [uv](https://docs.astral.sh/uv/getting-started/installation/), откройте терминал заново. Для первой загрузки зависимостей потребуется интернет.
3. Создайте рабочую копию. Команды рассчитаны на первый запуск. Если возвращаетесь к практике, откройте существующую папку `work/project`.

**Windows, PowerShell**

```powershell
cd exercises/04-meeting-tasks
New-Item -ItemType Directory -Force work/project/samples
Copy-Item samples/*.md work/project/samples/
cd work/project
claude
```

**macOS и Linux**

```sh
cd exercises/04-meeting-tasks
mkdir -p work/project/samples
cp samples/*.md work/project/samples/
cd work/project
claude
```

4. После запуска попросите Claude ответить одним словом «готов». Если клиент запросит вход или подтверждение аккаунта, завершите его и повторите запрос.
5. Держите рядом второй терминал в `work/project` для ручных проверок. Дальше цитаты вводите в Claude Code, команды в блоках с командами — во втором терминале.
6. Прочитайте [транскрипт](samples/meeting-2026-11-16.transcript.md). Найдите поручение, которое отменили, и поручение, срок которого перенесли. Запишите последние договорённости для сверки.

## 1. Создайте инструмент проверки

Откройте [испорченный протокол](samples/meeting-2026-11-16.broken.md). Посмотрите заголовки разделов и столбцы таблицы. Попросите агента создать только проверку.

> Создай scripts/check_protocol.py на стандартном Python. Команда принимает путь к протоколу и параметр --transcript с путём к исходнику. Формат таблицы возьми из samples/meeting-2026-11-16.broken.md. Проверь каждую задачу: назван исполнитель, срок — календарная дата в формате ГГГГ-ММ-ДД, метки времени есть в транскрипте. Найди телефон в тексте протокола. Выведи все нарушения с местом и причиной. Верни код 0 при успехе, 1 при нарушениях и 2 при ошибке чтения. Сохрани учебные файлы без изменений. Остановись после создания скрипта.

Запустите из второго терминала:

```sh
uv run --no-project scripts/check_protocol.py samples/meeting-2026-11-16.broken.md --transcript samples/meeting-2026-11-16.transcript.md
```

Сразу введите `echo $LASTEXITCODE` в PowerShell или `echo $?` в macOS/Linux. Ожидайте код 1 и три замечания. Найдите их в таблице сами: телефон, неопределённый исполнитель и неопределённый срок. Если скрипт считает слова «кто-нибудь» именем, уточните правило и повторите запуск.

## 2. Научите агента составлять протокол

> Создай проектный скилл .claude/skills/meeting-to-tasks/SKILL.md. Добавь name и description для разбора транскриптов. Опиши действия: установить дату встречи, проследить изменения решений, оставить последнее согласованное поручение. Требуй действие, исполнителя, дату и метку времени. Если реплик несколько, перечисляй их метки через запятую. Неполные поручения вынеси в открытые вопросы. Исключи личные подробности. Сохраняй решения, задачи и открытые вопросы в result/meeting-2026-11-16.protocol.md по формату учебного примера. Включи в SKILL.md заголовки разделов и пустую таблицу со всеми столбцами. Участник должен получить тот же формат в папке, где есть только транскрипт. Перемести существующую проверку в scripts/ внутри скилла. В инструкции укажи команду запуска из корня проекта с фактическими путями. При замечаниях исправь протокол и проверь снова. Сейчас подготовь только скилл.

Откройте созданный SKILL.md. Найдите правило для случая, когда участники перенесли срок. Завершите сеанс командой `/exit`, запустите `claude` из той же папки и отправьте:

> /meeting-to-tasks samples/meeting-2026-11-16.transcript.md

Откройте протокол. Должно получиться четыре задачи и четыре открытых вопроса. Сверьте перенесённый срок с исходной репликой. Проверьте, что отменённая договорённость отсутствует среди задач. Найдите в истории вызов скрипта. Повторите его вручную:

```sh
uv run --no-project .claude/skills/meeting-to-tasks/scripts/check_protocol.py result/meeting-2026-11-16.protocol.md --transcript samples/meeting-2026-11-16.transcript.md
```

Ожидайте код 0. Проверка формы может пройти даже при неверном решении встречи, поэтому сохраните сверку по репликам.

## 3. Проверьте разрешения и два хука

> Настрой только этот проект в .claude/settings.json. Запрети Edit и Write для *.transcript.md, WebSearch и WebFetch. Создай Python-обработчик в scripts/ рядом с проверкой. Подключи PreToolUse для Write и Edit: если в записываемый протокол попадает телефон, останови вызов и объясни причину. Подключи Stop: запусти нашу проверку для result/*.protocol.md и при ошибках верни агенту причины для исправления. Учти stop_hook_active, чтобы избежать цикла. Используй формат событий установленного Claude Code. Проверь команды запуска обработчиков в моей ОС, включая пути с пробелами. Покажи изменения и остановись.

Перезапустите Claude Code в проекте. Откройте `/permissions` и `/hooks`. Найдите добавленные правила и оба события. Проведите три отдельных опыта:

1. Попросите: «Через Edit добавь строку “тест” в учебный транскрипт. Если инструмент недоступен, остановись». Проверьте отказ и убедитесь, что исходник сохранился.
2. Попросите: «Через Edit добавь в готовый протокол учебный телефон из транскрипта. Сделай одну попытку». Найдите сообщение обработчика до записи. Откройте файл и проверьте, что телефон туда не попал.
3. Скопируйте испорченный протокол поверх результата. В PowerShell выполните `Copy-Item samples/meeting-2026-11-16.broken.md result/meeting-2026-11-16.protocol.md -Force`. В macOS/Linux выполните `cp samples/meeting-2026-11-16.broken.md result/meeting-2026-11-16.protocol.md`. Отправьте агенту «Ответь одним словом: готово». Проследите, как Stop возвращает замечания. После исправления повторите команду проверки из шага 2 и сверьте задачи по транскрипту.

Если агент сам отказался менять файл до вызова инструмента, срабатывание хука ещё не проверено. Попросите показать журнал вызова или прогнать обработчик отдельно на учебном событии. Отдельный прогон проверит обработчик; затем повторите опыт в клиенте.

## 4. Передайте задачи через MCP

> Создай локальный MCP-сервер tools/tasks_server.py на Python со стандартным транспортом stdio. Используй Python-пакет mcp версии 2.x, как на слайде «Свой MCP-сервер». Укажи зависимость mcp>=2,<3 в блоке метаданных скрипта для uv run. Добавь инструменты add_task и list_tasks. Храни задачи в meeting-tasks.csv в папке проекта, в UTF-8 с BOM для Excel. Сохраняй действие, исполнителя, дату и метку. Повторная передача той же задачи должна вернуть существующую запись. Зарегистрируй сервер в проектном .mcp.json. Проверь запуск, оставь список пустым для моего опыта.

Перезапустите клиент, подтвердите подключение проектного сервера и откройте `/mcp`. Найдите подключённый сервер и оба инструмента. Если сервер отключён, проверьте путь к `uv` и посмотрите ошибку запуска в клиенте.

> Передай согласованные задачи из готового протокола через add_task. Затем вызови list_tasks и покажи список.

Найдите четыре вызова добавления. Откройте CSV в Excel или текстовом редакторе и сверьте имена и даты с протоколом. Закройте файл. Попросите повторно вызвать add_task для каждой из тех же четырёх записей с теми же аргументами. Затем вызовите list_tasks. Ожидайте четыре записи после обеих передач. Если стало восемь, попросите исправить обработку повторов и повторите опыт с пустым учебным CSV.

## 5. Соберите плагин и испытайте его в другом проекте

> Упакуй созданные части в папку meeting-tasks внутри текущего проекта. Создай .claude-plugin/plugin.json, skills/meeting-to-tasks/, hooks/hooks.json, .mcp.json и файл сервера внутри плагина. Скопируй скрипты. В командах навыка, хуков и MCP укажи пути к ним через ${CLAUDE_PLUGIN_ROOT}. Учти пробелы в пути. Транскрипт читай из текущего проекта, протокол и CSV сохраняй там же. Проверь команды для моей ОС. Разрешения оставь в настройках исходного проекта. Покажи дерево плагина.

Выполните команды во втором терминале из `work/project`. Сначала проверьте состав плагина. Команда должна перечислить навык, оба хука и MCP-сервер. При ошибке исправьте плагин и повторите проверку. Затем подготовьте соседнюю папку с одним транскриптом.

**Windows, PowerShell**

```powershell
claude plugin validate ./meeting-tasks
New-Item -ItemType Directory -Force ../trial/samples
Copy-Item samples/*.transcript.md ../trial/samples/
cd ../trial
claude --plugin-dir ../project/meeting-tasks
```

**macOS и Linux**

```sh
claude plugin validate ./meeting-tasks
mkdir -p ../trial/samples
cp samples/*.transcript.md ../trial/samples/
cd ../trial
claude --plugin-dir ../project/meeting-tasks
```

В новой сессии откройте `/plugin` и найдите `meeting-tasks`. Вызовите `/meeting-tasks:meeting-to-tasks samples/meeting-2026-11-16.transcript.md`. Сверьте задачи и открытые вопросы по шагу 2. Из `work/trial` запустите проверку плагина:

```sh
uv run --no-project ../project/meeting-tasks/skills/meeting-to-tasks/scripts/check_protocol.py result/meeting-2026-11-16.protocol.md --transcript samples/meeting-2026-11-16.transcript.md
```

Ожидайте код 0. Повторите опыт с телефоном из шага 3 и отправьте задачи через MCP по шагу 4. Откройте CSV именно в `work/trial`. Если файл появился в первом проекте или внутри плагина, исправьте выбор рабочей папки и перезапустите клиент.

Практика пройдена, когда в новом проекте плагин составляет протокол, блокирует запись телефона и сохраняет четыре задачи без дублей. Для разбора сохраните путь к плагину, вывод проверки и пример срабатывания хука.
