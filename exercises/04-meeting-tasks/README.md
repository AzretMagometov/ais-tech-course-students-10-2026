# Из транскрипта встречи в список задач

Вы получите запись вымышленной встречи. На ней Полина меняет срок, а Марина отменяет одно из поручений. Ваша задача — собрать в Claude Desktop инструмент, который учитывает такие изменения и сохраняет согласованные задачи в таблицу. В конце вы передадите инструмент в другую папку и проверите, что он работает там.

## Откройте упражнение в Claude Desktop

Понадобятся распакованная папка курса, интернет и доступ к вкладке **Code** в настольном приложении Claude. Все запросы ниже вводите в поле сообщения. Файлы и команды обрабатывает Claude. Вы проверяете результат в приложении.

1. Откройте **Code** в боковой панели и начните новую сессию. Если видите только значки, наведите на них указатель.
2. Рядом с полем сообщения выберите **Local** и свой компьютер. Нажмите кнопку выбора папки → **Open folder…**. В распакованном курсе откройте `exercises` → `04-meeting-tasks`. Если приложение предлагает отдельную рабочую копию Git (*worktree*), оставьте её выключенной.
3. Отправьте запрос ниже. Если приложение попросит довериться папке, проверьте её название. Дождитесь ответа с путями к двум учебным файлам.

> Подготовь практику в этой папке. Скопируй оба файла из samples в work/project/samples, а в work/trial/samples — только транскрипт. Если возвращаюсь к практике, сохрани мою работу. Проверь, что можешь запустить Python через uv. Если uv отсутствует, скачай официальный исполняемый файл Astral для моей ОС в work/tools и проверь запуск. Покажи полный путь к рабочему uv и ссылки на оба файла в work/project/samples.

4. Нажмите путь к транскрипту в ответе. Найдите отменённое поручение и новый срок Полины. Запишите для себя две метки времени. Откройте испорченный протокол и посмотрите, из каких столбцов состоит таблица задач.
5. Начните **новую сессию Code**. Выберите **Local** и папку `04-meeting-tasks/work/project`. В этой папке пройдут шаги 1–4. Если Claude скачал uv в `work/tools`, скопируйте его полный путь из первого ответа и добавьте к следующему запросу.

Если вкладка Code предлагает войти в аккаунт или получить доступ, завершите этот шаг до начала практики. Расположение кнопок в разных версиях показано в [инструкции Anthropic по запуску Desktop](https://code.claude.com/docs/en/desktop-quickstart).

## 1. Найдите три ошибки в протоколе

> Создай scripts/check_protocol.py на стандартном Python. На вход он получает файл протокола и путь к оригиналу через --transcript. Возьми таблицу из samples/meeting-2026-11-16.broken.md. Для каждой задачи проверь, что назван исполнитель, указана календарная дата ГГГГ-ММ-ДД, а каждая метка времени есть в транскрипте. Проверь весь протокол на наличие телефона. Выведи место и причину каждой ошибки. Верни код 0 при успехе, 1 при нарушении, 2 при ошибке чтения. Запусти проверку на двух учебных файлах через uv. Покажи вывод и код завершения. Образцы сохрани в исходном виде.

В ответе раскройте действие, где Claude запускал проверку. Ожидайте код **1**. Сопоставьте замечания с тремя местами в протоколе. В одной задаче записан телефон, в другой исполнителем назван «кто-нибудь», в третьей срок указан словами «как будет время». Если что-то пропущено, назовите строку и попросите исправить скрипт и запустить его ещё раз.

## 2. Превратите разбор встречи в навык

> Создай проектный навык meeting-to-tasks в .claude/skills/meeting-to-tasks/SKILL.md. Включи в него названия разделов и шаблон таблицы из учебного протокола. Даты отсчитывай от даты встречи. При изменении срока бери последнюю договорённость. Для каждой задачи укажи действие, исполнителя, дату и метки подтверждающих реплик. Неполные поручения перенеси в открытые вопросы, личные подробности опусти. Записывай протокол в result рядом с папкой samples, замени в имени файла .transcript.md на .protocol.md. Перенеси скрипт в scripts внутри навыка. Добавь в навык запуск проверки и исправление замечаний. Покажи ссылку на SKILL.md. Сам разбор оставь для следующей сессии.

Откройте файл по ссылке и найдите правило о переносе срока. Начните новую сессию **Code** в той же папке `work/project`. В поле сообщения наберите `/`. Выберите **meeting-to-tasks**, допишите путь к записи и отправьте:

> /meeting-to-tasks samples/meeting-2026-11-16.transcript.md

Откройте `result/meeting-2026-11-16.protocol.md` по ссылке в ответе. В нём должны быть **четыре задачи и четыре открытых вопроса**. Сверьте срок Полины и отменённое поручение по своим двум меткам. Раскройте запуск скрипта и найдите код **0**. Если вызова нет, попросите Claude запустить проверку навыка на созданном файле и показать вывод.

## 3. Проверьте защиту исходника и протокола

> В настройках этого проекта .claude/settings.json запрети Edit и Write для транскриптов во вложенных папках, а также WebSearch и WebFetch. Добавь два хука — обработчика событий. PreToolUse должен остановить Edit или Write, если после операции в протоколе появится телефон. Stop должен проверить каждый result/*.protocol.md по соответствующему транскрипту и вернуть замечания для исправления. Учти stop_hook_active, чтобы избежать цикла. Положи обработчики рядом со скриптом проверки. Используй рабочий путь к uv и учти пробелы в путях. Покажи ссылки на настройки, испорченный образец и готовый протокол.

Начните новую сессию **Code** в `work/project`, чтобы загрузить настройки. Проведите три опыта по очереди.

| Что проверяете | Что сделать в приложении | Что должно произойти |
|---|---|---|
| Защита транскрипта | Отправьте «Попробуй через Edit добавить строку “тест” в транскрипт. Сделай одну попытку». | В истории виден отказ инструмента. В транскрипте нет добавленной строки. |
| Защита от телефона | Отправьте «Попробуй через Edit добавить учебный телефон Олега в готовый протокол. Сделай одну попытку». | Обработчик вернул причину до записи. Откройте протокол и убедитесь, что номера там нет. |
| Проверка перед завершением | Откройте испорченный образец по ссылке из предыдущей сессии и скопируйте его текст. В панели файла откройте **результат** в папке `result`, замените его содержимое скопированным текстом и сохраните. Вернитесь в новую сессию и отправьте «Ответь одним словом: готово». | Событие Stop вернуло ошибки скрипта. После исправления снова проверьте четыре задачи, четыре открытых вопроса и код 0. |

Для третьего опыта вы сами вносите учебную ошибку через редактор файла. Так можно увидеть работу Stop после сохранения. Если Claude ограничился словами «я бы отказался», попросите показать фактическое событие и ответ обработчика. Если в истории их нет, отметьте опыт как непроверенный.

## 4. Передайте задачи в таблицу через MCP

MCP позволяет Claude вызвать инструмент по имени. В этом шаге один инструмент добавляет задачу в CSV, другой читает список обратно.

> Создай локальный MCP-сервер tools/tasks_server.py с инструментами add_task и list_tasks. Используй Python, транспорт stdio и зависимость mcp>=2,<3 в метаданных скрипта для uv. Зарегистрируй сервер meeting-tasks в проектном .mcp.json. Укажи рабочий путь к uv. Храни действие, исполнителя, срок и метку времени в meeting-tasks.csv текущего проекта, кодировка UTF-8 с BOM. Повторный вызов с теми же данными должен вернуть существующую задачу. Проверь запуск. Оставь таблицу пустой для моего опыта.

Начните новую сессию **Code** в `work/project`. Если приложение предложит подключить сервер, выберите созданный вами **meeting-tasks**. Отправьте:

> Вызови list_tasks и покажи начальный список. Затем передай каждую из четырёх задач готового протокола через add_task. Вызови list_tasks ещё раз. Покажи результат и ссылку на CSV.

Откройте CSV по ссылке, сверьте имена и даты с протоколом. Затем отправьте:

> Повтори четыре вызова add_task с прежними аргументами и снова вызови list_tasks.

После двух передач ожидайте **четыре строки с задачами** плюс заголовок. Если Claude записал файл напрямую, попросите повторить опыт через подключённые инструменты. Если инструменты недоступны, попросите показать ошибку запуска сервера и проверить путь к uv в `.mcp.json`.

## 5. Испытайте плагин в новой папке

Сначала в сессии `work/project` соберите навык, два хука и MCP-сервер в один плагин.

> Собери папку meeting-tasks с манифестом .claude-plugin/plugin.json, навыком в skills/meeting-to-tasks, обработчиками в hooks/hooks.json и сервером из .mcp.json. Включи скрипты в комплект. Для файлов плагина используй ${CLAUDE_PLUGIN_ROOT}. Транскрипт, протокол и CSV должны находиться в текущем рабочем проекте. Сохрани правила разрешений в первом проекте. Проверь пути с пробелами и покажи состав плагина.

Вернитесь через боковую панель в **первую сессию**, открытую в `04-meeting-tasks`. Отправьте:

> Скопируй собранную папку work/project/meeting-tasks целиком в work/trial/.claude/skills/meeting-tasks. Проверь, что внутри копии есть .claude-plugin/plugin.json. В work/trial/samples должен лежать только транскрипт. Оставь создание протокола и CSV для новой сессии.

1. Начните новую сессию **Code → Local** и выберите папку `work/trial`. Подтвердите доверие к этой папке и подключение учебного MCP-сервера, если приложение спросит.
2. Наберите `/` и выберите **meeting-tasks:meeting-to-tasks**. Допишите `samples/meeting-2026-11-16.transcript.md` и отправьте. Префикс `meeting-tasks:` показывает, что вы вызываете навык плагина. Если он отсутствует, проверьте выбранную папку и полный путь к манифесту из предыдущего ответа. [Как Claude загружает плагины проекта](https://code.claude.com/docs/en/plugins/loading#plugins-shared-through-a-repository)
3. Откройте новый протокол. Повторите опыт с телефоном из шага 3, затем обе передачи задач из шага 4. Попросите Claude показать полные пути к протоколу и CSV.

**Практика пройдена**, когда в `work/trial` появились протокол и CSV, проверка протокола вернула 0, хук остановил запись телефона, а повторная передача сохранила четыре задачи. Для разбора сохраните путь к плагину, сообщение хука и итоговый список из четырёх строк.
