# Воркфлоу работы с агентом

В репозиторий включены четыре навыка Азрета и их справочные файлы.
Claude Code обнаруживает их в `.claude/skills/`, Codex — в `.agents/skills/`.
Обе папки содержат одинаковые обычные файлы. Глобальная установка и символические ссылки не нужны.
Копии адаптированы для учебного проекта: личные пути заменены локальными ссылками.
Глобальные настройки, память, история диалогов и рабочие проекты в комплект не входят.

## Этапы

| Навык | Что делает | Результат |
|---|---|---|
| [feature-discovery](../.claude/skills/feature-discovery/SKILL.md) | Обсуждает задачу и собирает требования | `notes.md` и `tech.md` |
| [create-prd](../.claude/skills/create-prd/SKILL.md) | Оформляет требования в спецификацию | `prd.md` и запись SPEC в проектном `CLAUDE.md` |
| [prd-to-beads](../.claude/skills/prd-to-beads/SKILL.md) | Готовит декомпозицию, затем переносит проверенные задачи в Beads | `tasks.md`, после ревью — задачи трекера |
| [senior-developer](../.claude/skills/senior-developer/SKILL.md) | Реализует одну назначенную задачу через тесты и проверки | Работающий и проверенный результат |

## Где работать

Для упражнения поиска дубликатов создайте отдельный проект в `exercises/02-duplicate-finder/work/`.
Укажите эту папку агенту как корень создаваемого проекта. Материалы задания и `samples/` сохраняйте без изменений.
Документы функции по умолчанию находятся в `docs/features/<slug>/` внутри выбранного проекта.
Например, в `exercises/02-duplicate-finder/work/docs/features/duplicate-finder/`.
Этот каталог `work/` исключён из Git студенческого репозитория.

Для работы со своим приложением подключайте навыки в его проекте.
Не добавляйте рабочие документы или ответы участников в публичный репозиторий курса.

## Запуск

В Claude Code откройте корень студенческого репозитория. Навыки находятся в `.claude/skills/`.
Начните с поручения, например:

```text
/feature-discovery
Обсудим приложение поиска дубликатов. Корень создаваемого проекта — exercises/02-duplicate-finder/work/.
```

После завершения обсуждения запускайте следующие навыки по очереди.
Передавайте фактический путь к папке функции, PRD или номер задачи, полученный на предыдущем этапе.
Не запускайте все этапы одним сообщением: обсуждение требований и проверка декомпозиции требуют вашего участия.

В Codex откройте корень студенческого репозитория. Выберите навык через `/skills` или укажите его через `$`:

```text
$feature-discovery
Обсудим приложение поиска дубликатов. Корень создаваемого проекта — exercises/02-duplicate-finder/work/.
```

Затем используйте `$create-prd`, `$prd-to-beads` и `$senior-developer` с результатами предыдущих этапов.
Для проверки знаний используйте `$study` с путём к материалу.
Если новые навыки не появились в списке, перезапустите Codex.

В другом клиенте укажите файл `.claude/skills/<имя>/SKILL.md` и попросите выполнить описанный процесс.
Справочные файлы читайте относительно папки навыка. Для работы вне учебного репозитория скопируйте четыре папки и `_shared` вместе.
Подключение через команду зависит от клиента. Если команда не обнаружена, используйте прямое чтение `SKILL.md`.

## Что потребуется

Обсуждение, PRD и черновик `tasks.md` используют файловые инструменты агента.
Для переноса задач в Beads и реализации по ним нужен установленный `bd` и база в целевом проекте.
В самом репозитории курса Beads не настроен. Не создавайте здесь базу ради учебной попытки.

Проверьте `bd --version`. Для работы по полному процессу отдельно попросите агента настроить Beads в проекте внутри `work/`.
Проверьте через `bd where`, что база относится к этому проекту. После настройки прочитайте `bd prime`. Флаги сверяйте со справкой установленной версии: `bd <команда> --help`.
Если `bd` отсутствует, агент должен сообщить об этом. Он не должен выдавать черновик за созданные задачи трекера.

В `prd-to-beads` сначала проверяют `tasks.md`, затем меняют статус на `reviewed` и поручают создание задач.
Этот перенос создаёт локальные задачи Beads. Он не означает коммит или отправку файлов в Git.

Context7 и дополнительные навыки проектирования необязательны: предусмотрены официальная документация и встроенные правила проектирования.
Если клиент поддерживает сабагентов, задачу реализации можно передать отдельному агенту.
Иначе используйте отдельную сессию с номером назначенной задачи и путями к спецификации.
Для реализации нужны инструменты выбранного языка. Устанавливайте и запускайте проверки по требованиям создаваемого проекта.

## Что изменено относительно оригиналов

- Ссылки на домашний каталог заменены справочниками внутри комплекта.
- Добавлено правило работы в выбранном проекте участника.
- Убрана обязательная зависимость от личных настроек, TodoWrite, Context7 и дополнительных навыков.
- Сохранены обсуждение концепта, структура PRD, ревью декомпозиции и цикл разработки через тесты.
- Публикация и коммиты подчиняются поручению участника и правилам проекта.
- Wayfinder не включён. Основной путь курса использует `notes.md` и `tech.md`. Чтение существующей карты осталось дополнительной возможностью.

## Сопровождение копий

Основной источник — `.claude/skills/`. Копии в `.agents/skills/` нужны для обнаружения в Codex.
При обновлении изменяйте основной источник и синхронизируйте соответствующие файлы для Codex.
Проверяйте одинаковый состав файлов и побайтовое совпадение содержимого.
