# AI Sprint: студенческий репозиторий

Это публичное рабочее место участника курса. Материалы ведущих и данные людей сюда не добавляются.
Общие правила для всех клиентов находятся в этом файле. Инструкция для участника: [воркфлоу работы с агентом](docs/agent-workflow.md).

## Общие правила

- Общайтесь по-русски. Код и комментарии в коде пишите по-английски.
- Начните с README.md и README.md выбранного упражнения.
- Выполняйте поручение участника. Не решайте остальные задания заранее.
- Используйте только разрешённые исходники. Если сведений нет, обозначьте отсутствие подтверждения.
- Не копируйте личные настройки, память, историю диалогов, ключи и рабочие документы в учебный комплект.
- В итоговом сообщении укажите путь результата, фактические проверки и ограничения.
- Не утверждайте, что проверка прошла, если её не запускали.
- Коммиты и публикацию выполняйте только по поручению пользователя.

## Выбор навыка

Прочитайте `SKILL.md` выбранного навыка перед выполнением его процесса.
Пути в таблице указаны от корня репозитория курса. Справочники разрешайте относительно папки навыка.
Claude Code загружает `.claude/skills/`, Codex — `.agents/skills/`.
В Codex вызывайте навыки через `$имя` или выбирайте через `/skills`.
Если клиент не поддерживает команды навыков, используйте прямое чтение файла.

| Поручение | Навык | Вход и результат |
|---|---|---|
| Проверить понимание прочитанного | `.claude/skills/study/SKILL.md` | Указанный материал → вопросы по одному и отчёт |
| Обсудить новую задачу или требования | `.claude/skills/feature-discovery/SKILL.md` | Описание участника → `notes.md` и `tech.md` |
| Собрать спецификацию | `.claude/skills/create-prd/SKILL.md` | Завершённое обсуждение → `prd.md` и запись SPEC |
| Разбить PRD на задачи | `.claude/skills/prd-to-beads/SKILL.md` | PRD → черновик `tasks.md`, после ревью — задачи Beads |
| Реализовать назначенную задачу | `.claude/skills/senior-developer/SKILL.md` | Задача Beads и спецификация → реализация с тестами |

Для полного процесса сохраняйте порядок: обсуждение → PRD → декомпозиция → реализация.
Используйте существующие результаты предыдущего этапа. Не проводите завершённое обсуждение заново без причины.
Выполняйте объём, порученный участником. Подключение навыка не разрешает автоматически пройти все этапы.
Если участник поручил весь процесс, продолжайте до следующего обязательного ответа или решения.
Не просите повторно подтвердить уже разрешённую работу.

## Проверка знаний

- Читайте указанный участником материал. Не отвечайте за него.
- Не меняйте учебные материалы во время проверки знаний.
- Сохраняйте отчёты локально в `exercises/01-study/results/`.
- Следуйте правилам study. Этапы разработки к проверке знаний не относятся.

## Проект участника

Перед записью определите корень целевого проекта и сообщите его участнику.
Для задачи дубликатов используйте `exercises/02-duplicate-finder/work/`.
Сохраняйте там код, настройки приложения и документы функции.
Документы функции по умолчанию: `<проект>/docs/features/<slug>/`.
Запись SPEC относится к `<проект>/CLAUDE.md`. Архитектурные решения относятся к документам этого же проекта.
Не записывайте спецификацию приложения в корневой `CLAUDE.md` репозитория курса.
Не меняйте `samples/`, материалы упражнения и проверки ради успеха приложения.
Для другой задачи используйте проект, указанный участником.

### Передача между этапами

- Discovery завершён только по критериям навыка. PRD получает фактические `notes.md` и `tech.md` из одной папки функции.
- Не додумывайте отсутствующие требования. Сохраняйте открытые вопросы или сообщайте, какие сведения блокируют следующий этап.
- В PRD укажите затрагиваемые файлы и функции в §6.5. По нему строится декомпозиция.
- В `prd-to-beads` сначала подготовьте черновик. Участник проверяет задачи и зависимости до переноса в трекер.
- Создавайте задачи из `tasks.md` со статусом `reviewed` по поручению участника. Не выдавайте черновик за созданные задачи.
- В реализацию передавайте номер задачи, пути к PRD и решениям. Перед правками прочитайте эти документы и SPEC.
- Реализуйте одну назначенную задачу через тесты. При изменении согласованного поведения обновляйте соответствующие документы проекта.

### Beads и инструменты

Beads в корне репозитория курса не настроен. Не инициализируйте здесь базу ради выполнения упражнения.
Обсуждение, создание PRD по заметкам и черновик задач работают без Beads.
Для переноса задач и реализации нужны установленный `bd` и база целевого проекта.

Перед работой проверьте `bd --version`, расположение базы через `bd where` и инструкции через `bd prime`.
База должна относиться к выбранному проекту. Не используйте случайно найденную родительскую базу.
Если проект не подготовлен, объясните недостающую настройку и предложите настроить его по поручению участника.
Не запускайте `bd init`, не создавайте отдельный Git-репозиторий и не настраивайте remote без такого поручения.
Проверяйте флаги по справке установленной версии: `bd <команда> --help`.

При поддержке сабагентов передавайте реализацию отдельному агенту с полным контекстом одной задачи.
Иначе используйте отдельную сессию. Не требуйте недоступных клиенту инструментов.
Context7 необязателен: используйте официальную документацию установленной версии библиотеки.
Проверки приложения выбирайте по его стеку и требованиям проекта.

## Сопровождение комплекта

Этот раздел относится к изменению навыков и учебных материалов по поручению владельца.
При проведении проверки знаний команды Git и проверки репозитория не нужны.
При сопровождении проверяйте локальные ссылки и выполняйте `git diff --check`.
При изменении навыков проверяйте их структуру, справочники и отсутствие личных данных.
Основной источник навыков — `.claude/skills/`. `.agents/skills/` — копия для обнаружения в Codex.
При изменении навыка обновляйте обе папки вместе со справочниками. Проверяйте побайтовое совпадение деревьев.
Храните обычные файлы: установка из ZIP и работа на Windows не должны требовать символических ссылок.
Не считайте проверки структуры подтверждением полного выполнения процесса.
