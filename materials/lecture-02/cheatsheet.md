# Claude Code: ситуация → действие

Памятка ко второй лекции. Документация сверена 11.11.2026.
Команды с `/` вводите в диалоге Claude Code. Команды `git`, `gh`, `bd` вводят в PowerShell или терминале.

## Контекст и сессии

| Ситуация | Терминал Claude Code | Desktop, вкладка Code |
|---|---|---|
| Понять состав контекста | `/context` | `/context` |
| Указать известный файл | `@путь` и вопрос | `@путь` или добавление файла в поле ввода |
| Сжать длинную историю | `/compact` с указанием, что сохранить | `/compact`; существенные итоги заранее сохраните в файл |
| Начать другую задачу | `/clear` | Новая сессия в той же локальной папке |
| Продолжить прежний разговор | `/resume` | `/resume` для локальной сессии или выбор сессии в списке |
| Дать разговору имя | `/rename имя` | Переименование в интерфейсе сессии |
| Задать побочный вопрос | `/btw вопрос` | `/btw`; также `Ctrl+;` на Windows, `Cmd+;` на macOS |
| Остановить ответ или действие | `Esc` | `Esc` |
| Открыть откат | `/rewind` или `Esc Esc` при пустом поле ввода | Для этой практики используйте терминал |
| Попробовать другое направление | `/branch имя` копирует разговор и переключает в него | Для этой практики используйте терминал |
| Запустить копию разговора в фоне | `/fork запрос` | Для этой практики используйте терминал |

Указание «используйте терминал» обозначает способ выполнения упражнения, а не запрет возможности во всех версиях Desktop.
Ввод `/` показывает доступные команды. В Desktop список клавиш открывается через `Ctrl+/` на Windows или `Cmd+/` на macOS.
Если команды нет, не вводите её в оболочку: выберите описанное действие в интерфейсе или пропустите дополнительный шаг.

Перед `/clear` и сжатием сохраните существенное в файле. Перед повторным использованием сверьте его с фактическим результатом.
`/branch` и `/fork` не обеспечивают изоляцию файлов. Остановка и откат не отменяют автоматически действия во внешних системах.

## Память

| Ситуация | Действие |
|---|---|
| Проверить инструкции и память | `/memory` в терминале; в Desktop при недоступности команды откройте файлы вручную |
| Найти личные файлы на Windows | Проводник → `%USERPROFILE%\.claude` |
| Найти личные файлы на macOS | Finder → `Cmd+Shift+G` → `~/.claude`; `Cmd+Shift+.` показывает скрытые файлы |
| Сохранить общее правило | Файл инструкций, уже принятый в проекте: например, `CLAUDE.md` |
| Сохранить личное правило проекта | `CLAUDE.local.md`; проверьте исключение из Git |
| Зафиксировать выбор | Журнал решений: дата, решение, причина, отклонённые варианты |
| Проверить источник «воспоминания» | Попросите назвать файл, затем откройте его и сверьте текст |

Файлы автоматической памяти находятся внутри `~/.claude/projects/` по умолчанию. Точный каталог уточняйте через `/memory`.
Не переносите личные заметки в публичный учебный репозиторий.

## Задачи и план

| Ситуация | Терминал Claude Code | Desktop |
|---|---|---|
| Сначала нужен план | `/plan` или `Shift+Tab` до режима plan | Переключатель режима под полем ввода → Plan |
| Открыть меню режимов | `Shift+Tab` переключает режимы | `Ctrl+Shift+M` на Windows, `Cmd+Shift+M` на macOS |
| Поправить предложенный план | Ответ с исправлением; `Ctrl+G` открывает внешний редактор | Ответ с исправлением |
| Посмотреть шаги текущей задачи | `Ctrl+T` в основном диалоге терминала | Попросите перечислить шаги и их состояние |
| Передать задачу новой сессии | После одобрения сохраните план в файл проекта | То же действие |
| Посмотреть фоновые задачи | `/tasks` | Меню ⋮ сессии → Background tasks |

Сохранение плана в проекте задавайте первым шагом выполнения после одобрения.
В новой сессии назовите путь плана и попросите сверить его с файлами.
Чек-лист текущей задачи, фоновые процессы и карточки общего трекера — разные списки.

В проекте с Git команда `git status --short --branch` показывает ветку и изменения отслеживаемых файлов.
Игнорируемые файлы в обычном выводе не видны. В этой практике результаты в `work/` нужно проверять непосредственно.
В копии из ZIP без `.git` проверяйте файлы и план без команды Git.

`gh issue list` и `bd ready` нужны только при наличии соответствующего инструмента и настроенного проекта.
Для упражнения устанавливать трекер или создавать публичные задачи не требуется.

## Запрос состояния

```text
Прочитай план и проверь фактические файлы задачи.
Что выполнено, что осталось, какие решения нужны от меня?
Для каждого критерия готовности укажи проверку и результат.
Если проверка не запускалась или недоступна, скажи об этом.
Рабочие файлы не меняй. Назови следующий шаг.
```

Для программы добавьте сборку и тесты, если они настроены. Для документа — проверку разделов, ссылок и источников.
Запуск проверок иногда создаёт файлы или меняет окружение. Сначала уточните такие действия, если нужна проверка без изменений.
