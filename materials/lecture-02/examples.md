# Образцы: правило, решение и план

Примеры относятся к учебной памятке. Адаптируйте их к своей задаче и существующим документам проекта.
Не копируйте весь комплект в каждый проект: сохраняйте только нужные сведения.

## Общее правило проекта

Ниже — пример содержимого файла инструкций проекта. Укажите существующий файл, когда поручаете агенту записать правило.

```markdown
# Правила учебной папки

- Результаты сохраняй в work/. Материалы курса не меняй.
- Перед записью назови целевой файл.
- Ссылки проверяй относительно файла, в котором они находятся.
- В итоговом ответе перечисли выполненные проверки и непроверенное.
```

Правила описывают наблюдаемые действия. Здесь нет списка текущих ошибок или истории обсуждения одной задачи.
Перед добавлением проверьте, не записано ли такое же правило в другом месте.

## Личное правило

Для проверки загрузки `CLAUDE.local.md` можно использовать заметное ограничение:

```markdown
Отвечай не длиннее пяти строк, если я не прошу подробно.
```

Добавляйте его к существующему содержимому файла без перезаписи других правил.
В новой сессии задайте короткий вопрос и проверьте ответ. Затем откройте сам файл.
Совпадение стиля одного ответа не доказывает загрузку: дополнительно проверьте список инструкций через `/memory`, если он доступен.

## Запись решения

Ниже учебный пример записи для `decisions.md`. В своей записи укажите фактическую дату принятия решения.

```markdown
## 10.11.2026. Результаты практики в отдельной папке

Контекст: упражнение повторяется несколько раз в одной копии курса.
Решение: результаты сохраняем в exercises/03-context-and-plan/work/.
Причина: исходные материалы остаются пригодны для следующей попытки.
Отклонено: редактирование корневого README, поскольку он служит оглавлением курса.
```

Причина помогает понять, когда решение стоит пересмотреть. При новом решении укажите связь с предыдущим.

## План с состоянием

Это пример состояния после создания первого раздела. Отметки `[x]` описывают пример, а не вашу выполненную работу.

```markdown
# Памятка по второй лекции

## Цель
Создать summary.md с четырьмя темами лекции.

## Источник и границы
Источник: materials/lecture-02/lecture.md от корня курса.
Результат: exercises/03-context-and-plan/work/summary.md.
Изменять только файлы внутри work/. Исходный текст лекции не менять.

## Готово, когда
- Есть разделы «Контекст», «Память», «Задачи и план», «Состояние».
- В каждом разделе указаны ситуация, действие и проверка результата.
- Из summary.md открывается относительная ссылка на текст лекции.
- Все четыре раздела сверены с источником.

## Шаги
- [x] Прочитать источник и согласовать структуру.
- [x] Создать раздел «Контекст».
- [ ] Дополнить три остальных раздела.
- [ ] Проверить содержание и ссылку.

## Состояние
Создан только раздел «Контекст». Остальные разделы ещё не написаны.
Проверено вручную: первый раздел содержит ситуацию, действие и проверку.
Ссылка пока не проверена.
Следующий шаг: написать раздел «Память» по исходному тексту лекции.

## Открытые вопросы
Нет.
```

Для своей попытки создайте план до выполнения. Отмечайте шаги по результату, а не по ожиданию.
Раздел состояния позволяет продолжить работу без отдельного `state.md`.
Если в проекте уже есть трекер, сохраняйте основной статус там и ссылайтесь на него из документов.

## Запрос передачи работы

```text
Обнови план по фактическим файлам: сделанное, проверки, ограничения и следующий шаг.
Не отмечай непроверенное как готовое. Покажи, какие записи изменены.
```

В новой сессии:

```text
Прочитай exercises/03-context-and-plan/work/plan.md и названные в нём источники.
Сверь состояние с файлами. Назови следующий шаг и противоречия, если они есть.
Пока ничего не меняй.
```
